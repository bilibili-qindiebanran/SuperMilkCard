# SuperMilkCard ↔ ESP32 局域网通信接口文档

本文档面向 ESP32 硬件开发者，描述桌面软件（SuperMilkCard）与 ESP32 设备在局域网内的通信协议。ESP32 作为**服务器**，桌面软件作为**客户端**。

- 软件端协议实现参考：`Windows/src/main/services/esp32.ts`、`Windows/src/main/services/framing.ts`、`Windows/src/main/services/perfMonitor.ts`
- 所有多字节整数均为**大端序（Big Endian）**。

---

## 1. 总体架构

```
┌──────────────────────┐          TCP (服务器)          ┌──────────────────────┐
│   SuperMilkCard      │  ◄──────────────────────────►  │        ESP32         │
│   （客户端）          │                               │       （服务器）       │
│                      │  WebSocket (服务器)            │                      │
│                      │  ────────────────────────────► │                      │
└──────────────────────┘                               └──────────────────────┘
        ▲  UDP 监听 4210（设备发现广播）
```

| 通道 | 协议 | 方向 | 用途 |
|------|------|------|------|
| 设备发现 | UDP | ESP32 → 软件 | ESP32 广播识别码与连接参数 |
| 语音输入 | TCP | ESP32 → 软件 | 麦克风采集的音频 → 转文字 |
| 文本传输 | TCP | 双向 | 聊天文本收发 |
| 语音输出 | TCP | 软件 → ESP32 | 软件 TTS 音频 → ESP32 播放 |
| 性能监测 | WebSocket | 软件 → ESP32 | CPU/GPU/内存使用率实时推送 |

默认端口：

| 端口 | 协议 | 说明 |
|------|------|------|
| 9000 | TCP | ESP32 业务数据服务器 |
| 9001 | WebSocket | 性能数据服务器 |
| 4210 | UDP | 设备发现广播（ESP32 发送，软件监听） |

> 端口均可通过软件设置界面修改；UDP 发现端口 4210 为协议固定值。

---

## 2. 设备识别码

每个 ESP32 设备需有一个唯一**识别码（deviceId）**，建议使用芯片 ID 或 MAC 地址（如 `esp32_8f3a2b1c`）。识别码用于：

1. **设备发现**：随 UDP 广播下发，供软件在设备列表中展示与选择。
2. **连接校验**：TCP 连接建立后，ESP32 需发送握手帧，软件校验识别码与用户所选一致。

---

## 3. 设备发现（UDP）

ESP32 周期性（建议 1~3 秒）向局域网广播端口 `4210` 发送 UDP 广播/组播（目标地址 `255.255.255.255` 或组播地址均可，软件监听 `0.0.0.0:4210`）。

载荷为 UTF-8 JSON 字符串：

```json
{
  "id": "esp32_8f3a2b1c",
  "name": "桌面小助手",
  "tcpPort": 9000,
  "wsPort": 9001
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | string | 是 | 设备识别码 |
| name | string | 否 | 设备显示名 |
| tcpPort | number | 否 | TCP 服务器端口，缺省 0（软件回退到配置默认值） |
| wsPort | number | 否 | WebSocket 服务器端口，缺省 0（软件回退到配置默认值） |

软件收到广播后，以 **UDP 源 IP** 作为设备主机地址，将识别码映射到 `{host, tcpPort, wsPort}`，供用户选择连接。

---

## 4. TCP 帧协议

TCP 为字节流，需通过帧头界定消息边界。软件侧已实现粘包/半包处理与错误重同步。

### 4.1 帧格式

```
偏移    长度    内容
0       1       魔数 0xAA
1       1       魔数 0x55
2       1       帧类型 type
3       4       负载长度 length（uint32 大端，不含帧头 7 字节）
7       length  负载 payload
```

帧头共 **7 字节**。单帧负载最大 **4 MiB**（超过视为非法帧，软件会丢弃并重同步）。

### 4.2 帧类型

| type | 名称 | 负载 |
|------|------|------|
| 0x01 | HELLO | UTF-8 JSON（握手，见 §5） |
| 0x02 | TEXT | UTF-8 JSON 字符串（文本/控制消息，见 §6） |
| 0x03 | AUDIO | 二进制音频数据（见 §7、§8） |

---

## 5. 握手（HELLO 帧）

TCP 连接建立后，**ESP32 应立即发送一条 HELLO 帧**（type = 0x01），负载为 JSON：

```json
{
  "id": "esp32_8f3a2b1c",
  "name": "桌面小助手"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | string | 是 | 设备识别码 |
| name | string | 否 | 设备显示名 |

软件行为：

- 若用户配置了识别码且 HELLO 中的 `id` 与之不一致，软件**断开连接并提示**。
- 校验通过后，软件进入 `connected` 状态，开始收发业务数据。

---

## 6. 文本消息（TEXT 帧）

TEXT 帧负载为 UTF-8 JSON 字符串。通过 JSON 的 `type` 字段区分消息种类。

### 6.1 聊天文本（软件 → ESP32）

软件将聊天消息下发给 ESP32：

```json
{
  "type": "chat",
  "role": "user",
  "content": "你好"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| type | string | 固定 `"chat"` |
| role | string | `"user"`（用户）或 `"assistant"`（助手回复） |
| content | string | 完整文本内容（UTF-8） |

### 6.2 设备文本（ESP32 → 软件）

ESP32 向软件发送文本（展示于软件设置页 ESP32 状态区）：

```json
{
  "type": "text",
  "content": "设备已就绪"
}
```

### 6.3 音频开始（控制帧）

开始一段音频传输（音频数据随后通过 AUDIO 帧发送）：

```json
{
  "type": "audio_start",
  "format": "pcm",
  "sampleRate": 16000,
  "channels": 1,
  "bits": 16
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| type | string | 是 | 固定 `"audio_start"` |
| format | string | 是 | `"pcm"`（语音输入）或 `"mp3"`（语音输出） |
| sampleRate | number | 否 | 采样率（PCM 时建议 16000） |
| channels | number | 否 | 声道数（PCM 时建议 1） |
| bits | number | 否 | 位深（PCM 时建议 16） |

### 6.4 音频结束（控制帧）

表示一段音频传输结束：

```json
{
  "type": "audio_end"
}
```

## 7. 语音输入（ESP32 → 软件 → 转文字）

流程：

```
ESP32                                 软件
  │  TEXT: audio_start(pcm,16000,1,16)  │
  ├───────────────────────────────────► │ 开始累积
  │  AUDIO 帧（PCM 小端）                │
  ├───────────────────────────────────► │ 累积二进制
  │  ... 可多帧 ...                      │
  │  TEXT: audio_end                     │
  ├───────────────────────────────────► │ 结束累积
  │                                     │  PCM → WAV → STT
  │                                     │  识别结果 → 聊天输入框
```

要求：

- 音频格式：**16-bit 有符号 PCM，小端序**，默认 16 kHz 单声道。
- 每帧音频负载 ≤ 4 MiB，可分多帧发送。
- 软件收到 `audio_end` 后，将 PCM 封装为 WAV 并调用语音转文字（STT）模块，识别结果回填聊天输入框。

---

## 8. 语音输出（软件 → ESP32 → 播放）

流程：

```
软件                                   ESP32
  │  TEXT: audio_start(mp3)             │
  ├───────────────────────────────────► │ 准备播放
  │  AUDIO 帧（MP3 字节，32KB 分片）      │
  ├───────────────────────────────────► │ 累积
  │  ... 可多帧 ...                      │
  │  TEXT: audio_end                     │
  ├───────────────────────────────────► │ 开始解码播放
```

要求：

- 音频格式：**MP3**（软件端 TTS 模块输出 MP3）。
- ESP32 需具备 **MP3 解码能力**（如 ESP-ADF 或 Helix MP3 解码器）后经 I2S/DAC 播放。
- 音频被拆分为多个 AUDIO 帧发送，每帧负载约 32 KiB，ESP32 需累积到 `audio_end` 后统一播放（或边收边解码，取决于实现）。

---

## 9. 性能监测（WebSocket）

软件作为 **WebSocket 客户端**，连接 ESP32 的 WebSocket 服务器（默认 `ws://<host>:9001`），将选定的性能数据以 JSON 文本实时推送。

推送消息格式：

```json
{
  "type": "perf",
  "ts": 1754700000000,
  "cpu": 42.3,
  "gpu": null,
  "memory": 63.1
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| type | string | 固定 `"perf"` |
| ts | number | 采样时间戳（毫秒） |
| cpu | number \| null | CPU 使用率（0~100） |
| gpu | number \| null | GPU 使用率（0~100，平台不可用时为 null） |
| memory | number \| null | 内存使用率（0~100） |

- 仅包含用户在设置中勾选的监测项目，未勾选项**不出现在消息中**。
- 推送间隔由设置决定（默认 1000 ms）。
- 软件与 WebSocket 服务器断开后自动重连（间隔 5 s）。

---

## 10. 重连与错误处理

### 10.1 TCP 重连

- 软件作为客户端，断线后自动重连。
- 重连采用**指数退避**：基础间隔（默认 1000 ms，可配置）每次失败 ×2，上限 **30 s**。
- 重连成功后，需重新走 §5 握手流程。

### 10.2 数据完整性

- 软件按帧头长度累积字节，处理半包/粘包。
- 魔数错位时逐字节重同步。
- 单帧长度超过 4 MiB 视为非法帧并丢弃。

### 10.3 超时建议（ESP32 侧）

- TCP 建议开启 keepalive 或应用层心跳，及时发现断线。
- 语音输入若长时间无 `audio_end`，建议 ESP32 侧设置超时并主动结束。

## 11. 消息帧字节示例

### 例 1：ESP32 发送握手帧

JSON：`{"id":"esp32_8f3a2b1c"}`（22 字节 UTF-8）

```
AA 55 01 00 00 00 16 7B 22 69 64 22 3A 22 65 73 70 33 32 5F 38 66 33 61 32 62 31 63 22 7D
│  │  │  └─ 长度 22 ─┘ └──────────── payload (22 字节) ────────────┘
│  │  └─ type 0x01 (HELLO)
└──└─ 魔数 AA 55
```

### 例 2：软件发送聊天文本

JSON：`{"type":"chat","role":"user","content":"hi"}`

```
AA 55 02 <length> <JSON bytes...>
```

### 例 3：性能数据（WebSocket，纯文本）

```json
{"type":"perf","ts":1754700000000,"cpu":42.3,"memory":63.1}
```

## 12. 常量汇总

| 常量 | 值 | 说明 |
|------|-----|------|
| 魔数 | `0xAA 0x55` | 帧头前两字节 |
| 帧头长度 | 7 字节 | 魔数 2 + 类型 1 + 长度 4 |
| 单帧最大负载 | 4 MiB | 超过则丢弃 |
| UDP 发现端口 | 4210 | ESP32 广播，软件监听 |
| 默认 TCP 端口 | 9000 | 可配置 |
| 默认 WebSocket 端口 | 9001 | 可配置 |
| 重连基础间隔 | 1000 ms | 指数退避，上限 30 s |
| WebSocket 重连间隔 | 5000 ms | 固定 |
